# 신규 총기 기획 절차

새 총 한 정을 이 데모에 추가할 때 **무엇을 어떤 순서로 정하는가**. 절차를 끝까지 따라가면 [`data/weapons.json`](../data/weapons.json) 항목 하나가 빈칸 없이 채워진다.
필드의 뜻은 [총기 감각 구성요소 분해](총기%20감각%20구성요소%20분해.md), 기존 4정의 값과 그 결과는 [총기별 세팅 비교표](총기별%20세팅%20비교표.md)를 본다.

전체 흐름: **① 정체성 한 줄 → ② 정체성을 실을 축 → ③ 값 채우기(9단계) → ④ 사격장 검증 → ⑤ 파일에 넣고 문서 갱신**

---

## ① 정체성을 한 줄로 쓴다

값을 하나라도 정하기 전에, 이 총을 든 사람이 **무엇을 하게 되는가**를 한 문장으로 쓴다. 값은 전부 이 문장에서 역산한다.

| 4정의 예 | 한 줄 |
|---|---|
| CS형 | 궤적을 외워서 이기는 총. 암기 전과 후가 다른 총이 된다 |
| PUBG형 | 거리에 따라 풀오토 → 버스트 → 단발로 행동이 갈리는 총 |
| COD형 | 반동은 순하지만 조준하지 않으면 못 맞히는 총. 실력이 조준 이전 단계에 있다 |
| 루트슈터형 | 끊어 쏘기만 하면 게임이 반동을 대신 잡아주는 총 |

이 문장이 없으면 ③에서 값을 "적당히" 고르게 되고, 결과는 기준 AR의 변주에 그친다.

## ② 정체성을 실을 축을 하나 고른다

네 축 중 **하나**가 정체성을 만들고, 나머지 셋은 그것을 받쳐준다. 두 축 이상에 정체성을 실으면 어느 것도 눈에 띄지 않는다.

| 축 | 이 축에 정체성을 두면 | 받쳐주는 방식 (4정 예) |
|---|---|---|
| **반동** | 총이 미는 모양과 예측 가능성이 곧 총이다 | CS형: 퍼짐을 극단적으로 좁혀 반동만 남김. PUBG형: 복귀를 느리게 해 반동이 오래 남게 |
| **퍼짐** | 자세(지향/정조준/이동)를 강제한다 | COD형: 반동을 최소로 해 퍼짐만 문제가 되게 |
| **복귀** | 손을 뗀 뒤의 일이 총의 성격이다 | 루트슈터형: 반동을 순하게 해 복귀가 다 잡을 수 있게 |
| **정조준** | 조준 전환의 값(시간·효과)이 교전 방식을 정한다 | 아직 이 축만으로 정체성을 만든 총은 없다. 예: `ads.time` 500 ms + `ads.spread` 0.05 → 준비된 교전에서만 강한 저격형 AR |

답할 질문: **기존 4정과 겹치지 않는가?** 같은 축, 같은 방향이면 값만 다른 변주다. 다른 축을 고르거나, 같은 축에서 반대 방향을 고른다.

## ③ 값 채우기 — 9단계

순서가 중요하다. 앞 단계의 값이 뒤 단계의 범위를 정한다. 각 단계에 **권장 범위**(튜닝 패널 슬라이더 범위와 4정 값의 분포)와 **정하기 전에 답할 질문**을 적었다.

### 3-1. `rpm`, `mag` — 반동이 쌓이는 속도와 길이

| 필드 | 권장 범위 | 4정 |
|---|---|---|
| `rpm` | 550~800 (AR). 슬라이더 300~1200 | 600 / 660 / 750 / 600 |
| `mag` | 25~35. 슬라이더 10~60 | 30 / 30 / 30 / 33 |

- 질문: 한 탄창을 몇 초 만에 비우는가? (`mag × 60000/rpm`). 4정은 2.3~3.2 s.
- `rpm`은 발당 반동을 **초당** 반동으로 바꾼다. 같은 `v0`라도 750 rpm은 600 rpm보다 25 % 빨리 쌓인다. 반동 값을 정한 뒤 rpm을 올리면 총이 통째로 사나워진다.
- 패턴은 40발까지 펼쳐지므로 `mag`가 40을 넘으면 뒤 1/3이 반복된다. 넘길 이유가 없으면 40 이하.

### 3-2. `pattern.mode`와 수직 — 총이 미는 모양

먼저 `curve`인지 `array`인지 정한다.

| 모드 | 언제 | 정할 것 |
|---|---|---|
| `curve` | 반동이 "공식"이면 충분할 때. 대부분의 총 | `v0` `vG` `vMax` |
| `array` | 발마다 손으로 그린 궤적이 필요할 때 (학습형). 무작위를 0으로 둘 때만 의미가 있다 | `arr` 30발 `[v, h]` |

`curve` 수직:

| 필드 | 권장 범위 | 4정 | 질문 |
|---|---|---|---|
| `v0` (°) | 0.12~0.40. 슬라이더 0~1.5 | 0.36 / 0.15 / 0.22 | 첫 발에 얼마나 튀는가. 0.15는 "순함", 0.36은 "묵직함" |
| `vG` (°/발) | 0.005~0.03. 슬라이더 0~0.1 | 0.026 / 0.014 / 0.008 | 긁을수록 심해지는가(0.026), 거의 일정한가(0.008) |
| `vMax` (°) | v0의 1.3~2배. 슬라이더 0~2 | 0.62 / 0.30 / 0.30 | 발당 상한. `(vMax − v0) / vG`발째에 도달한다 |

- 한 탄창 누적 수직 = 대략 `mag × (v0 + vMax) / 2`. 4정은 5.8~17°. **10° 넘으면 플레이어가 반드시 끌어내려야 하는 총**, 6° 아래면 복귀에 맡길 수 있는 총이다.
- `array`라면: 1~7발 수직 급상승 → 8발부터 수직 0.04 + 수평 지그재그처럼 **구간을 나눠** 그린다. 구간이 없는 배열은 curve와 구별되지 않는다.

### 3-3. 수평 — 외울 수 있는가

| 필드 | 권장 범위 | 4정 | 질문 |
|---|---|---|---|
| `hMode` | `fixed-alt` / `random` | random / fixed-alt / fixed-alt | **외워서 이길 수 있는 총인가?** `random`이면 아니다 |
| `h0` (°) | 0.03~0.08. 슬라이더 0~0.3 | 0.072 / 0.034 / 0.038 | `fixed-alt`에서 좌우 교대 폭. 수직의 1/5 정도가 기준 AR 비율(5:1) |
| `hMax` (°) | h0의 1.3~2배. 슬라이더 0~0.5 | 0.13 / 0.05 / 0.05 | `random`이면 **발당 ±hMax가 그대로 흔들림 폭** |

- `random`을 고르면 한 탄창 뒤 수평 위치의 표준편차 ≈ `hMax × sqrt(mag / 3)`. PUBG형 0.13° × sqrt(10) ≈ 0.41°. 이 값이 25 m에서 ±18 cm다. 원거리에서 풀오토를 무력화하려면 이 정도, 살짝 흔들리는 정도면 0.06° 이하.

### 3-4. `randV`, `randH` — 학습을 얼마나 방해하는가

| 필드 | 권장 범위 | 4정 | 질문 |
|---|---|---|---|
| `randV` | 0~0.25. 슬라이더 0~1 | 0 / 0.10 / 0.12 / 0.06 | 수직 노이즈는 관대하다(사람은 세로로 길다). 0.25까지 무난 |
| `randH` | 0~0.10. 슬라이더 0~1 | 0 / 0.10 / 0.05 / 0.03 | 수평 노이즈는 잔인하다. `fixed-alt`의 좌우 상쇄를 깨지 않으려면 0.05 이하 |

- 학습형이면 **둘 다 0**. 0.01이라도 있으면 "매번 같은 그림"이 깨진다.
- `randH`는 `fixed-alt`에서는 거의 안 느껴지고(좌우 교대가 상쇄), `random`에서는 hMax 위에 곱해져 흔들림을 살짝 키운다.

### 3-5. `recovery` — 손을 떼면 누가 잡는가

| 필드 | 권장 범위 | 4정 | 질문 |
|---|---|---|---|
| `delay` (ms) | 40~200. 슬라이더 0~500 | 80 / 160 / 60 / 45 | 발 간격(3-1)보다 짧으면 연사 중엔 어차피 안 돈다. 끊어 쏠 때 "잠깐 멈춤"이 느껴지는 문턱이 약 100 ms |
| `speed` (°/s) | 5~30. 슬라이더 0~40 | 13 / 5 / 16 / 26 | 풀 반동 복귀 시간 = `delay + 누적/speed`. 이 시간을 먼저 정하고 역산한다 |

- 목표 복귀 시간을 정한다: **0.1 s 이하** = 자동 리센터(루트슈터형), **0.5 s 안팎** = 도와주지만 기대면 안 됨(CS·COD형), **재장전 시간(2 s) 초과** = 플레이어 몫(PUBG형).
- 5발 버스트 기준으로도 계산해 본다. 5발 누적 ≈ `5·v0 + 10·vG`. 루트슈터형은 1.18° → 45 + 45 = 90 ms.
- 복귀는 **보정분 제외**다. 플레이어가 끌어내린 만큼은 안 돌아온다. 복귀가 빠른 총일수록 "끌어내리지 말라"는 메시지가 된다.

### 3-6. `spread` — 어떤 자세를 강제하는가

| 필드 | 권장 범위 | 4정 | 질문 |
|---|---|---|---|
| `base` (°) | 0.10~0.55. 슬라이더 0~2 | 0.10 / 0.42 / 0.50 / 0.30 | 지향사격을 믿을 수 있는가. 25 m 원 지름 = `2 × tan(base) × 25 m`: 0.1° → 9 cm, 0.5° → 44 cm |
| `bloom` (°/발) | 0.015~0.05. 슬라이더 0~0.2 | 0.018 / 0.040 / 0.026 / 0.022 | 연사를 벌하는가 |
| `max` (°) | base의 1.5~3배. 슬라이더 0~3 | 0.36 / 0.85 / 0.95 / 0.45 | 원이 커질 수 있는 한계 |
| `decay` (°/s) | 1.2~2.5. 슬라이더 0~5 | 2.2 / 1.4 / 2.0 / 2.4 | 손을 뗀 뒤 회복 속도. **연사 중엔 ×0.25** |

- **연사 중 원이 실제로 자라게 하려면** `bloom > decay × 0.25 × 발간격(s)`이어야 한다. 660 rpm이면 발 간격 0.091 s, decay 1.4 → 회복 0.032°/발. bloom 0.040이면 발당 +0.008° 자란다 (PUBG형). bloom이 이보다 작으면 원은 한 발치만 커지고 끝난다 (나머지 3정).
- 사람 표적 폭은 약 0.5 m. 25 m에서 원 지름이 이 폭을 넘는 순간 지향사격은 "운"이 된다. 조준을 강제하려면 base 0.5° 이상.

### 3-7. `ads` — 조준을 강제하는가, 허용하는가, 없애는가

| 필드 | 권장 범위 | 4정 | 질문 |
|---|---|---|---|
| `allowed` | true / false | false / true / true / true | ADS를 없애려면 `base`가 0.15° 이하여야 총이 성립한다 |
| `recoil` | 0.6~0.9. 슬라이더 0~1.5 | 1 / 0.85 / 0.60 / 0.80 | 정조준하면 반동도 순해지는가 |
| `spread` | 0.1~0.45. 슬라이더 0~1.5 | 1 / 0.18 / 0.12 / 0.40 | 지향 대비 몇 배 좁아지는가. `base × spread` = 정조준 원. 4정은 0.06~0.12° |
| `time` (ms) | 180~400. 슬라이더 0~600 | 0 / 350 / 220 / 200 | 조준 전환 비용. 250 ms가 기준 AR. 350이면 "무겁다", 200이면 "가볍다" |

- `base`(3-6)와 `spread`는 **한 쌍**이다. 지향 원 ÷ 정조준 원의 비율이 "조준의 가치"다: COD형 8배(필수), 루트슈터형 2.5배(선택).
- `time`은 `delay`(3-5)와 리듬을 맞춘다. 복귀보다 조준이 오래 걸리면 "쏘고 → 내려오고 → 다시 조준"의 박자가 생긴다.

### 3-8. `cap` — 안전망이 필요한가

| 필드 | 권장 범위 | 4정 | 질문 |
|---|---|---|---|
| `on` | true / false | 전부 false | 한 탄창 누적 수직(3-2)이 화면 밖으로 나갈 만큼 큰가 |
| `deg` (°) | 4~10. 슬라이더 0~15 | 8 / 7 / 4 / 5 (꺼져 있음) | 켠다면 누적 수직의 40~60 %. 그 이상이면 켜도 안 걸린다 |

- 4정은 모두 껐다. 17°까지 올라가는 PUBG형도 껐다 — "손으로 잡아야 한다"가 정체성이라 안전망이 정체성을 깎기 때문. 켤 이유가 분명할 때만 켠다 (예: 60발 탄창 LMG형).

### 3-9. 3D 전투 값 — 4정과 같게 두는 것이 기본

| 필드 | 기본값 | 바꿀 때 |
|---|---|---|
| `damage` | 200 | 표적 HP 3000이 15발에 맞춰져 있다. 바꾸면 TTK가 4정과 달라져 **감각 비교가 오염**된다. 3단계 데모에서는 같게 |
| `headshotMul` | 1.5 | 같게 |
| `falloff` | `{ start: 20, end: 50, minRatio: 0.5 }` | 같게 |
| `reloadTime` (s) | 2.0 | 복귀 시간(3-5)과 비교하라. 복귀가 이보다 길면 재장전 후에도 카메라가 올라가 있다 |
| `moveSpreadMul` | 2.0 | 걸으며 쏘는 총을 만들려면 1.3 이하, 벌하려면 3 이상 |

마지막으로 표시 항목: `id`(영문 소문자, 4정과 겹치지 않게), `name`, `tag`(대문자 영문 한 구절 — 정체성 축을 적는다).

## ④ 사격장에서 검증한다

값을 파일에 넣기 전에 **튜닝 패널로 먼저 느껴본다.** 코드를 건드리지 않고 값만 바꿔 즉시 반영된다.

1. `npm run dev` → 브라우저 → ESC로 마우스 잠금 해제 → **왼쪽 아래 무기 튜닝 패널**.
2. 정체성 축이 가장 가까운 기존 총을 든다(1~4). 그 총의 슬라이더를 ③에서 정한 값으로 옮긴다. 값은 localStorage에 남아 새로고침해도 유지된다.
3. 아래 체크리스트를 25 m 과녁판에서 확인한다.

| # | 확인 | 어디서 | 통과 기준 |
|---|---|---|---|
| 1 | 흰 궤적의 모양이 ①의 문장과 맞는가 | P로 궤적 표시 | "묵직하다"인데 궤적이 짧으면 3-2로 |
| 2 | 궤적과 실제 자국의 차이가 의도한 만큼인가 | 한 탄창 연사, X로 지우고 반복 | 학습형이면 두 번 쏜 자국이 겹쳐야 한다. 무작위형이면 궤적 좌우 막대 안에 흩어져야 한다 |
| 3 | 손을 떼면 의도한 시간 안에 돌아오는가 | 5발 쏘고 떼기, 마우스 고정 | 조준 원이 첫 발 자리(궤적 원점)로 돌아온다. 시간은 3-5 계산과 비교 |
| 4 | 우클릭에 조준 원이 의도한 만큼 줄어드는가 | 우클릭 유지 | 지향 원 ÷ 정조준 원 비율이 3-7 의도와 맞는다. ADS 없는 총은 아무 변화가 없어야 한다 |
| 5 | 걸으면서 쏘면 벌을 받는가 | W 누른 채 사격 | 원이 커지고 자국이 흩어진다 |
| 6 | **다른 3정과 자국 모양이 구별되는가** | 4정 순서대로 한 탄창씩, 색으로 비교 | 눈으로 구별되지 않으면 ②로 돌아간다 — 변주에 그친 것 |

4. 통과하면 패널의 **"JSON 복사"** → `weapons.json` 항목 형식 그대로 클립보드에 들어온다.

## ⑤ 파일에 넣고 문서를 갱신한다

1. `data/weapons.json`의 `weapons` 배열에 복사한 항목을 붙인다. `id`·`name`·`tag`를 새 총 것으로 바꾼다.
2. 값이 빠지거나 타입이 틀리면 게임이 **화면에 경고를 띄우고 기본값(기준 AR)으로 진행**한다. 경고가 뜨면 그 필드를 고친다. 게임은 멈추지 않는다.
3. 탄착 자국 색: `src/ui/weaponColors.js`의 `WEAPON_COLORS`에 새 `id`의 색을 넣는다. 안 넣으면 회색.
4. 무기 전환 키는 라인업 순서(1~4)와 휠 순환을 따른다. 5정째부터는 휠로만 전환된다 (숫자키는 4까지).
5. [총기별 세팅 비교표](총기별%20세팅%20비교표.md) 표 A에 열을 추가하고, 표 B는 값을 게임 코드로 돌려 채운다 (손계산 금지). 무기별 해설 한 절을 쓴다.
6. 튜닝 패널의 "파일 값으로 초기화"로 실험 값을 지운다.
