# 결정 로그

인터뷰에서 무엇을 물었고 사용자가 무엇을 골랐는지의 기록. **왜 그 값인지**를 되짚을 때, 그리고 3단계 산출물
"신규 총기 기획 절차" 문서를 쓸 때의 재료로 쓴다.

- 현재 유효한 규칙 → [CLAUDE.md](../CLAUDE.md) · 현재 유효한 기획 → [SPEC.md](../SPEC.md) · 최초 지시문 → [킥오프 원문](킥오프%20원문.md)
- 이 문서는 **기록**이다. 여기 값과 SPEC이 다르면 **SPEC이 최신**이다.

## 1. 킥오프 인터뷰 (2026-09-03) — 8개 주제

### 주제 1. 시뮬레이터 이해 확인

| 질문 | 사용자 선택 |
|---|---|
| 요약이 맞는가. 특히 `recovery`의 "보정분 제외"(총이 밀어올린 오프셋만 되돌리고 플레이어가 내린 조준각은 그대로) 해석 | **전부 맞다** |
| 3D 이식 시 무기 스키마 유지 범위 | **구조 재설계 허용** (필드명·구조는 3D에 맞게, 값의 의미·단위는 보존) |

| 그대로 재현할 세부 룰 (복수 선택) | **네 가지 전부** — cap 클램프 / 패턴 인덱스 순환(뒤 1/3, 정지 500ms 리셋) / 사격 중 bloom ×0.25 / 원형 균등 탄착 분포 |

### 주제 2. 엔진·프로젝트 세팅

| 질문 | 사용자 선택 |
|---|---|
| 엔진·플랫폼 | **웹 + Three.js** |
| 버전 관리 | git 사용, **Claude가 초기화** |
| `docs/총기 시뮬레이터.html` 취급 | **무기 값의 원본 소스로 사용** |
| 티켓 완료 확인 방식 | **로컬 서버 URL 열어 직접 플레이** |
| 언어 | **JavaScript (ESM)** |
| 빌드 | 처음엔 "백엔드 없이 단일 HTML" → 충돌 발견 후 **Vite 빌드**(개발은 서버, 제출은 `dist/index.html` 단일 파일) |
| Three.js 도입 | **npm 패키지, 버전 고정** |
| 폴더 구조 | T01에서 제안받겠다 → **T01에서 승인** |

> **충돌 처리 기록**: "단일 HTML" + "npm Three.js" + "데이터 JSON 분리" + "더블클릭 실행"은 그대로 양립하지 않는다.
> 제시한 두 안 중 **Vite 빌드**를 선택. 개발 중엔 모듈로 나누고 빌드 시 하나로 합쳐 오프라인 더블클릭을 만족시킨다.

| 지향 FOV | **90°** |
| 마우스 감도 | **기본 8.0 / 범위 1~30** (°/100px, 시뮬레이터 동일 단위) |

| 질주 / 웅크리기 배율 | **×1.5 / ×0.5** |
| 관성 | **짧은 가속·감속** (즉시 정지 아님) |
| 눈높이 | **1.7m / 1.0m** |

| 벽 충돌 | **벽을 따라 미끄러짐** |
| 이동 중 사격 | **이동속도 비례 퍼짐 증가, 무기별 배율 설정 가능.** 질주 중 사격 불가, 사격 입력 시 질주 해제 |

| 질문 | 사용자 선택 |
|---|---|
| 무기 값의 최종 소스 | 처음엔 "시뮬레이터에서 꺼내 시트로 이사" → **최종: 시트 불필요, 하드코딩** |

> 런타임에 시트를 읽으면 오프라인 더블클릭 제약과 충돌한다. 사용자가 "몇 개 안 될 것 같다"며 하드코딩으로 전환.

## 4. 번복·변경 이력

킥오프 원문 또는 앞선 결정에서 **바뀐 것들.** 새로 합류하는 사람이 원문과 현재 상태의 차이에 혼란하지 않도록 남긴다.

| 항목 | 처음 | 최종 | 이유 |
|---|---|---|---|
| 3단계 총기 수 | 6종 중 **3정** | **4정** (CS·PUBG·COD·데스티니형) | 사용자가 3단계 인터뷰에서 변경 |
| 기준 AR | 3단계에도 포함 예상 | **사격장에서 제외** | 2단계 개발용으로만 쓰기로 |
| 데이터 소스 | Google Sheets → JSON 변환 | **하드코딩** (무기 JSON이 곧 소스) | 계정 접근 불가 + 오프라인 제약 + 양이 적음 |
| 데이터 파일 범위 | 무기·몬스터·웨이브·드랍 전부 파일 | **무기만 파일**, 나머지는 코드 | 위와 같은 흐름 |
